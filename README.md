# Nostalgia Duel / دوئل نوستالژی

بازی فقط آنلاین برای وب و اندروید، ساختهٔ **استودیو جولی پاندا — [jollypanda.ir](https://jollypanda.ir)**. همهٔ مسابقه‌ها در سرور Colyseus محاسبه می‌شوند؛ بازی آفلاین، تمرین محلی و انتخاب نوبتی روی یک دستگاه حذف شده‌اند. فعلاً سرور فقط روی سیستم میزبان و LAN اجرا می‌شود؛ میزبانی عمومی فعال نشده است.

## اجرا

Node 22.12+ لازم است. ابتدا npm ci و سپس START-GAME.cmd یا START-ONLINE.cmd را اجرا کنید؛ هر دو بازی را می‌سازند و سرور را روشن نگه می‌دارند. معادل: npm run build و npm run start:online. روی سیستم میزبان http://127.0.0.1:2567 و روی دستگاه دوم آدرس LAN همان سیستم را باز کنید. توسعهٔ رابط با npm run dev نیز به سرور بازی روی 2567 نیاز دارد.

فایل out/play.html که با node scripts/standalone.mjs ساخته می‌شود فقط کلاینت بسته‌بندی‌شده است و برای بازی همچنان به سرور نیاز دارد؛ هنگام قطع اتصال حالت آفلاین جایگزین نمی‌شود. خروجی وب در dist و ZIP در out است.

## دوستان و دعوت

- از «پروفایل و تنظیمات» فقط نام و آواتار خودت، تعداد دورهای دوئل و ظرفیت دورهمی را تعیین کن.
- در «دوستان»، کد هشت‌کاراکتری خودت را کپی کن یا کد دوستت را وارد کن. دوستی پس از قبول درخواست دوطرفه می‌شود؛ درخواست را می‌توان رد/لغو و دوست را حذف کرد.
- وضعیت حضور، درخواست‌ها و دعوت‌ها هر ۳ ثانیه به‌روز می‌شوند. فهرست‌ها چهار مورد در هر صفحه دارند؛ صفحه اسکرول ندارد.
- «دعوت به بازی» برای دوست تأییدشده، در صورت نداشتن میز، یک اتاق دوستان با حالت و ظرفیت فعلی می‌سازد و دعوت ۶۰ ثانیه‌ای می‌فرستد. دریافت‌کننده در تب «دعوت‌ها» ورود را انتخاب می‌کند. دعوت فقط به میز دوستانِ باز و دارای جای خالی ممکن است؛ وسط مسابقه یا از میز جست‌وجوی سریع دعوت نمی‌فرستیم.
- میزبان پس از آماده‌شدن همه شروع می‌کند. بازیکنی که پشت میز دیگری است، ابتدا باید از آن خارج شود تا دعوت را قبول کند. شروع/پرشدن/بسته‌شدن میز یا پایان مهلت، دعوت را نامعتبر می‌کند.
- هویت فعلی مهمان و وابسته به مرورگر و آدرس سرور است؛ توکن در localStorage و فقط هش آن در سرور نگهداری می‌شود. ورود با ایمیل/موبایل و بازیابی حساب روی دستگاه دیگر هنوز اضافه نشده است. پاک‌کردن دادهٔ مرورگر یا عوض‌کردن مبدأ آدرس می‌تواند هویت مهمان تازه بسازد.
- پروفایل‌ها، درخواست‌ها و دوستی‌ها در .local/social.json روی میزبان ذخیره می‌شوند (از Git خارج است). حفظ فایل برای نگهداری دوستان لازم است. دعوت‌ها و حضور کوتاه‌مدت‌اند و با راه‌اندازی مجدد سرور پاک می‌شوند.

## بازی و آموزش

سه حالت: کلاسیک، دوئل پیشرفتهٔ پنج‌حرکتی، پلم پولوم پلیچ ۳ تا ۸ نفره. دوئل‌ها ۱/۳/۵/۷/۹ دور غیرمساوی دارند؛ دورهمی با یک دوئل کلاسیک تمام می‌شود. مسابقهٔ سریع پس از ۵ ثانیه ظرفیت خالی را با حریف کامپیوتری تکمیل می‌کند؛ داخل مسابقه برچسب/ظاهر متمایز ندارد. هر انتخاب ۵ ثانیه فرصت دارد؛ حرکت ناتمام تصادفی معتبر ثبت می‌شود. نتیجه و محرمانگی انتخاب‌ها با سرور است.

«راهنما» نمودار تعاملی ژست‌ها و فلش‌های برد، سه مثال دورهمی و توضیح کوتاه شروع آنلاین دارد. ژست‌ها و نگارگری اختصاصی در assets هستند. [مرجع معرفی نسخهٔ پیشرفته](https://fa.wikipedia.org/wiki/سنگ-کاغذ-قیچی) و [Sam Kass / Karen Bryla](https://www.samkass.com/theories/RPSSL.html)؛ تصاویر نمودار آن صفحات کپی نشده‌اند.

رکوردهای نتیجهٔ آنلاین روی همین دستگاه ذخیره می‌شوند؛ جدول جهانی نداریم. [راهنمای LAN و سرور](docs/ONLINE.fa.md)، [بررسی طراحی](design-qa.md) و [برنامهٔ درآمد](docs/MONETIZATION.fa.md). تبلیغ، پرداخت و تله‌متری فعلاً خاموش‌اند.

## Android / CI

App id: `com.jollypanda.nostalgiaduel` (slug: `nostalgiaduel`, repository: `nostalgia-duel`). `npm run android:prepare` creates/syncs ignored android/. `STORE=debug npm run build:android` (PowerShell: `$env:STORE='debug'; npm run build:android`) produces a standalone debug APK in out plus a web ZIP. Local Android SDK 36 required. Debug app id has `.debug` suffix; never submit debug APK to a store.

`.github/workflows/prototype.yml` provides a manually triggered APK + web test build without release keys or store submission. It retains contents:read and artifact upload; no automated private Release delivery is enabled. Artifact storage is currently full. Per the owner's choice, only local web output is needed for now; no new workflow run, permanent signing key or central-builder activation is performed in this update. The workflow verifies debug package identity, APK signature and portrait orientation on a future run. Main release pipeline remains the template's central builder contract: main for development, Iranian-store for builds, web=true, separate Bazaar/Myket targets. Creating a repo does not automatically authorize the central builder GitHub App. When using setup later, pass --repo nostalgia-duel with --slug nostalgiaduel to preserve the selected identity. No publisher should be enabled for this prototype.

## تب‌های پایین

میدان بازی، پروفایل، رکوردها و راهنما چهار tab هستند که محتوای اصلی صفحه را تغییر می‌دهند. نوار نزدیک لبهٔ پایین و مستقل از مقیاس محتوای بازی ثابت است؛ فضای امن گوشی و ارتفاع نوار از فضای محتوای وسط کم می‌شود. تب‌ها با کلیدهای جهت، Home و End هم قابل جابه‌جایی‌اند. تست: node scripts/test-tabs-browser.mjs.

## رابط مسابقه

در مسابقه فقط تنظیمات بالای صفحه می‌ماند. کارت‌های امتیاز، برد و وضعیت حذف بازیکنان بالای میز هستند؛ نوار زمان پیوسته از زمان سرور کم می‌شود. دو ثانیهٔ آخر برای بازیکنی که انتخاب نکرده، حاشیهٔ صفحه با آهنگ ملایم یک بار در ثانیه هشدار می‌دهد (در reduced-motion ثابت است). نتیجهٔ هر دور از سرور شامل برنده، امتیاز همان دست، حذف یا تساوی است و وسط میز نمایش داده می‌شود.

تنظیمات شامل روشن/خاموش‌کردن صدای تولیدشدهٔ بازی، بلندی صدا، ویبره و خروج با تأیید است. تنظیمات در localStorage می‌مانند؛ مسابقه هنگام بازبودن تنظیمات متوقف نمی‌شود. ویبره به پشتیبانی مرورگر/دستگاه وابسته است و در نبود آن کنترل غیرفعال می‌شود. صدای بازی پس از تعامل کاربر فعال می‌شود. تست: node scripts/test-match-hud.mjs.

## نتیجهٔ مسابقه

پس از پایان، صفحهٔ مستقل Match Result جای میز را می‌گیرد: قهرمان، امتیاز و برد نهایی هر بازیکن، تعداد دست‌ها و سه دست آخر با انتخاب صفحه. در مسابقهٔ سریع هر نفر می‌تواند جست‌وجوی تازه را شروع کند؛ در اتاق دوستان، میزبان مسابقهٔ دوباره با همان جمع را آغاز می‌کند. برگشت به میدان از نتیجه بدون تأیید خروجِ مسابقهٔ جاری انجام می‌شود. خلاصهٔ دورها فقط پس از پایان از سرور ارسال می‌شود. تست: node scripts/test-match-result.mjs.

## ورودی و پاداش آزمایشی

با کلیک روی هر کارت مود، پنجرهٔ تأیید ورودی/جایزه باز می‌شود؛ کادر پروفایل و تنظیماتِ بالای دکمهٔ شروع از میدان حذف شده است. پروفایل از تب خودش قابل ویرایش است و تنظیم صدا/ویبرهٔ مسابقه حفظ شده. موجودی شروع مهمان ۳۰۰ سکه و ۰ XP است؛ خرید و برداشت واقعی وجود ندارد.

| مود | ورودی سکه | جایزهٔ قهرمان | XP سایر بازیکنان پس از پایان |
|---|---:|---|---:|
| کلاسیک | ۲۰ | ۳۵ سکه + ۳۰ XP | ۱۰ |
| پیشرفته | ۴۰ | ۷۰ سکه + ۵۰ XP | ۱۵ |
| دورهمی | ۳۰ | ۱۲۰ سکه + ۸۰ XP | ۱۵ |

جست‌وجو و انصراف پیش از شروع هزینه ندارند. ورودی در شروع واقعی، از موجودی معتبر سرور کسر می‌شود. در میز دوستان، هزینه و جایزه پیش از آماده‌بودن نمایش داده می‌شود و هر مسابقهٔ مجدد ورودی تازه دارد. لغو قبل از نتیجه، ورودی را به بازیکنان برمی‌گرداند؛ پاداش فقط پس از پایان و یک بار ثبت می‌شود. موجودی ناکافی ورود را مسدود می‌کند. نتیجهٔ مسابقه سکه/XP دریافتی و موجودی نهایی را نشان می‌دهد. کیف پول و تراکنش‌ها در همان .local/social.json هستند؛ پس از توقف و راه‌اندازی مجدد، ورودی‌های مسابقه‌های ناتمام برمی‌گردند. مقادیر در src/economy.js متمرکزند. تست‌ها: tests-online/economy.test.mjs و scripts/test-entry-browser.mjs.

## پروفایل، نام و آواتار

تب پروفایل فقط آواتار بزرگ، نام با ویرایش مدادی، لول/XP و آمار کلی و تفکیک‌شدهٔ سه مود دارد. برگشت، آماده‌ایم، تعداد بازیکنان و تنظیم دور از این تب حذف شده‌اند؛ دور و ظرفیت فقط در پنجرهٔ شروع انتخاب می‌شوند. نام ۳ تا ۱۶ کاراکتر دارد و روی سرور یکتا است؛ شکل‌های عربی/فارسی ی و ک، ارقام، فاصله‌ها و حروف کوچک/بزرگ هنگام بررسی تکرار همسان می‌شوند. نام‌های تکراری قدیمی در مهاجرت پسوند می‌گیرند.

۱۰ آواتار اختصاصی قصه‌ها و حماسه‌های ایرانی در assets/avatars نگهداری می‌شوند. رستم، شهرزاد و عمو نوروز رایگان‌اند؛ گردآفرید/زال/سهراب/تهمینه/سیمرغ/ملانصرالدین/حسن کچل به ترتیب ۸۰/۱۰۰/۱۲۰/۱۴۰/۱۶۰/۱۸۰/۲۰۰ سکه‌اند. انتخاب آواتار قفل و تغییر سکه از کلاینت پذیرفته نمی‌شود؛ خرید تکراری یک آواتار دوباره هزینه ندارد. نام، مالکیت و انتخاب آواتار، آمار و سکه در فایل اجتماعی سرور می‌مانند. آمار فقط برای مسابقهٔ تمام‌شده ثبت می‌شود و پرداخت تکراری، آمار را تکرار نمی‌کند. هر ۱۰۰ XP یک لول است. آمار بازی‌های نسخه‌های قبلی بازسازی نشده؛ XP و سکهٔ قبلی حفظ می‌شوند.

دارایی‌ها با ابزار داخلی ImageGen ساخته شده‌اند؛ اطلس اصلی atlas-v1.png، ده WebP و PROMPT.txt کنار هم هستند. تست‌ها: tests-online/profile.test.mjs و scripts/test-profile-browser.mjs.

## تب دوستان و حرکت بین تب‌ها

«دوستان» از هدر به نوار پایین منتقل شده و پنجمین tab/tabpanel است. فهرست دوستان، درخواست‌ها و دعوت‌ها داخل محتوای صفحه باز می‌شوند. دسترسی «دعوت دوستان» از اتاق همچنان در پنجرهٔ داخل همان اتاق کار می‌کند. محتوای تب‌ها با ورود ۲۳۰ میلی‌ثانیه‌ای و نشانگر متحرک جابه‌جا می‌شوند؛ انتخاب کاهش حرکت دستگاه، حرکت را غیرفعال می‌کند. تست‌ها: scripts/test-tabs-browser.mjs و npm run test:browser.

زمان مرحله از ۵ ثانیه به ۳ ثانیه کاهش خطی دارد (گردشده به ۱۰۰ میلی‌ثانیه). در دوئل، تعداد دورهای غیرمساوی و در دورهمی تعداد حذف‌ها میزان پیشرفت است. تساوی و نبود تک مرحله را مصرف نمی‌کنند؛ دوئل نهایی دورهمی و وقت اضافهٔ دوئل ۳ ثانیه‌اند. تک‌راندی از ابتدا ۳ ثانیه است. نوار زمان از مدت واقعی ارسال‌شدهٔ سرور استفاده می‌کند؛ جست‌وجوی حریف همچنان ۵ ثانیه است. پاداش مطابق شرایط ثبت‌شده هنگام کسر ورودی تسویه می‌شود. تست‌ها: tests/tournaments.test.mjs، tests-online/tournaments.test.mjs و scripts/test-tournaments-browser.mjs.


## انتخاب آرنا

دکمه‌های شروع و با دوستان از خانه حذف شده‌اند. هر مود مستقیماً پنجرهٔ کارت‌های آرنا را باز می‌کند؛ فلش‌ها، کشیدن افقی، کلیدهای چپ/راست و نقطه‌ها کارت را عوض می‌کنند. هر آرنا تصویر اختصاصی، هزینه، پاداش سکه و XP و شرط لول دارد. آرناهای کلاسیک و پیشرفته ۱/۳/۵/۷/۹ راند و به‌ترتیب لول ۱/۲/۳/۴/۵ هستند. دورهمی ۳ تا ۸ نفر (۲ تا ۷ مرحلهٔ تعیین‌کننده) در لول‌های ۱ تا ۶ باز می‌شود. تساوی تعداد دست‌های واقعی را بیشتر می‌کند. انتخاب‌ها برای هر مود جداگانه در همین نشست حفظ می‌شوند.

قفل لول روی سرور هنگام ساخت، پیوستن، مچ‌میکینگ و کسر ورودی بررسی می‌شود. XP هر ۱۰۰ واحد یک لول است؛ تغییر مقدار کلاینت قفل را باز نمی‌کند. تب دوستان مسیر دعوت و دکمهٔ اتاق دوستان / کد دعوت را دارد. تصاویر شانزده‌گانه با ImageGen ساخته شده و اطلس و پرامپت در assets/arenas ذخیره شده‌اند. تنظیم آرناها: src/arenas.js. تست‌های جدید: tests-online/arenas.test.mjs و node scripts/test-arenas-browser.mjs.


## فروشگاه سکه با تأیید خودکار شبکه

تب فروشگاه و + کنار موجودی، سه بستهٔ ۱۰۰۰ / ۳۰۰۰ / ۸۰۰۰ سکه را نمایش می‌دهند. XP فروخته نمی‌شود. آدرس‌های عمومی ETH و BNB و BTC از https://www.useffarahmand.com/en/support در ۲۰۲۶-۱۱-۰۹ تطبیق داده شدند؛ هیچ کلید خصوصی نیاز نیست. قیمت‌های پایهٔ فعلی برای بسته‌ها: ETH: 0.0003 / 0.0006 / 0.0015، BNB: 0.001 / 0.002 / 0.005، BTC: 0.0001 / 0.0002 / 0.0005. این‌ها قیمت ثابتِ ارز اصلی هستند، تبدیل نرخ دلار نیستند؛ مقادیر در online/ShopService.mjs تغییر می‌کنند.

هر فاکتور دو ساعت مهلت پرداخت دارد و سرور مبلغ یکتای کوچکی به قیمت پایه اضافه می‌کند: ETH حداکثر 0.000000999، BNB حداکثر 0.00000999 و BTC حداکثر 0.00000999. مبلغ دقیق، شبکه، مقصد و QR استاندارد پرداخت روی فاکتور نمایش داده می‌شوند؛ کارمزد شبکه جداست. از ولتی استفاده شود که مبلغ دقیق را ارسال می‌کند. پرداخت از صرافی با مبلغ کسرشده/گردشده یا ارسال توکن تأیید نمی‌شود.

بازیکن پس از ارسال، TXID/Hash را وارد و بررسی را می‌زند. سرور مستقل از کلاینت، شبکه، مقصد، مقدار دقیق و بلاک بعد از صدور فاکتور و در مهلت آن را بررسی می‌کند. ETH فقط پس از finalized، BNB پس از ۱۵ تأیید و BTC پس از ۶ تأیید و تطبیق بلاک اصلی پذیرفته می‌شود. یک تراکنش یک بار مصرف می‌شود؛ مبلغ اختصاصی هر سفارش هرگز دوباره تخصیص داده نمی‌شود تا تراکنش عمومی شخص دیگر قابل ادعا نباشد.

سفارش و پرداخت در همان فایل .local/social.json همراه موجودی ذخیره می‌شوند؛ سکه فقط بعد از تأیید و ذخیره ثبت می‌شود. بررسی سفارش‌های pending با TXID ثبت‌شده هر ۲۰ ثانیه در سرور ادامه دارد، حتی وقتی صفحه بسته است. صفحه نیز هر ۱۵ ثانیه بررسی می‌کند. تاریخچهٔ هشت سفارش آخر بازیکن قابل بازکردن است. فایل داده و توکن مهمان مرورگر باید برای بازیابی خریدها نگهداری شوند. این ذخیره‌ساز مخصوص سرور تک‌پردازهٔ محلی است؛ چند نمونهٔ همزمان باید به پایگاه دادهٔ تراکنشی مهاجرت کنند. آدرس RPCها در .env.example آمده؛ محیط باید آن‌ها را به node بدهد (فایل env خودکار بارگذاری نمی‌شود). در نبود شبکه هیچ سکه‌ای ثبت نمی‌شود و خطا برای تلاش مجدد نمایش داده می‌شود.

QR با qrcode به‌صورت محلی ساخته می‌شود و مبلغ و آدرس به سرویس QR خارجی فرستاده نمی‌شوند. قالب‌ها: EIP-681 برای ETH/BNB و BIP-21 برای BTC. استعلام‌ها فقط‌خواندنی‌اند؛ سرور نه تراکنش می‌سازد و نه امضا می‌کند. تست‌ها: npm run test:shop و tests-online/shop.test.mjs؛ مسیر تأیید با پاسخ‌های کنترل‌شدهٔ شبکه تست شده، نه انتقال پول واقعی. دسترسی خواندن ارتفاع هر سه شبکه اصلی جداگانه بررسی شد.
