# بیلد، امضا و خرید دوئل ترنج

شناسهٔ اندروید `com.jollypanda.nostalgiaduel` است. شناسهٔ APK آزمایشی `com.jollypanda.nostalgiaduel.debug` است و می‌تواند کنار نسخهٔ امضاشده نصب شود.

## بیلد خودکار

با هر push به `main`، GitHub Actions تست‌ها را اجرا می‌کند، نسخهٔ بعد را با توجه به تگ‌های قبلی می‌سازد و پس از موفقیت بیلد، تگ `vX.Y.Z` و فایل‌ها را در **Releases** ثبت می‌کند. اجرای دستی **Android releases** نیز می‌تواند نسخهٔ اصلی، فرعی یا اصلاحی ایجاد کند. APK دیباگ برای آزمون آفلاین است. هر فروشگاهی که امضا و کلید خریدش تنظیم شده باشد APK و AAB امضاشده دارد. فایل SHA256 کنار خروجی‌ها قرار می‌گیرد. انتشار در پنل فروشگاه مرحله‌ای جداگانه است.

برای تست دستگاه از GitHub استفاده کنید یا با JDK 21 و Android SDK Platform 36 و Build Tools 36.0.0 در یک checkout تازه بسازید:

```powershell
npm ci
$env:STORE = 'debug'
$env:ANDROID_GAMEPLAY_ONLY = 'true'
npm run build:android
```

## تنظیم امضا و خرید

در **Settings → Secrets and variables → Actions** این مقادیر را تعریف کنید:

| نوع | نام | مقدار |
| --- | --- | --- |
| Secret | `KEYSTORE_BASE64` | Base64 فایل کلید امضا |
| Secret | `KEYSTORE_PASSWORD` | رمز فایل کلید |
| Secret | `KEY_ALIAS` | نام کلید، برای نمونه `toranj` |
| Secret | `KEY_PASSWORD` | رمز کلید |
| Variable | `BAZAAR_RSA_KEY` | کلید عمومی خرید درون‌برنامه‌ای از پنل کافه‌بازار |
| Variable | `MYKET_PUBLIC_KEY` | کلید عمومی خرید درون‌برنامه‌ای از پنل مایکت |

برای تولید کلید اولین انتشار، خارج از ریپو با `keytool -genkeypair -v -keystore toranj-release.jks -storetype JKS -alias toranj -keyalg RSA -keysize 2048 -validity 10000` شروع کنید. برای انتشارهای بعدی همان فایل و نام کلید را نگه دارید. اگر از قبل نسخه‌ای منتشر شده است، از کلید قبلی استفاده کنید.

در هر دو پنل، این شناسه‌ها را به‌صورت **محصول مصرف‌شدنی** بسازید. قیمت را در پنل تنظیم کنید. بازی قیمت اعلام‌شده از همان فروشگاه را نمایش می‌دهد.

| شناسه | سکه |
| --- | ---: |
| `toranj_coins_300` | ۳۰۰ |
| `toranj_coins_600` | ۶۰۰ |
| `toranj_coins_1000` | ۱٬۰۰۰ |
| `toranj_coins_2000` | ۲٬۰۰۰ |
| `toranj_coins_3500` | ۳٬۵۰۰ |
| `toranj_coins_6000` | ۶٬۰۰۰ |

خرید در APK هر فروشگاه از SDK همان فروشگاه انجام می‌شود. رسید در دستگاه اعتبارسنجی و سکه پیش از مصرف رسید ثبت می‌شود. خرید پرداخت‌شده و مصرف‌نشده با «به‌روزرسانی» دوباره بررسی می‌شود. موجودی اندروید روی دستگاه است. برای انتقال موجودی بین دستگاه‌ها یا بازیابی پس از حذف برنامه، ذخیرهٔ حساب سمت سرور لازم است.

## تست پیش از انتشار

- گوشی کوچک و تبلت، حالت پرواز، هر سه حالت بازی، بازگشت از پس‌زمینه و ماندگاری پیشرفت.
- در هر فروشگاه با حساب تست همان پنل، نمایش ریالی، خرید موفق، لغو، قطع ارتباط بعد از پرداخت و بازیابی بدون دوبار اضافه‌شدن سکه.
- نصب نسخهٔ امضاشده و به‌روزرسانی آن با نسخه‌ای با کد بالاتر، با حفظ داده‌ها.
