# اجرای آنلاین و دوستان در شبکهٔ داخلی

START-GAME.cmd و START-ONLINE.cmd هر دو پس از ساخت خروجی وب، سرور روی پورت ۲۵۶۷ را اجرا می‌کنند. سرور باید روشن بماند. آدرس سیستم میزبان http://127.0.0.1:2567 است؛ روی گوشی یا رایانهٔ دوم آدرس LAN چاپ‌شده در خروجی سرور را باز کنید. هر دو دستگاه به یک شبکه متصل شوند. هیچ فایروالی به‌طور خودکار تغییر نمی‌کند. بازی اینترنت عمومی هنوز راه‌اندازی نشده است.

## مسیرهای بازی

۱. پروفایل خودت، حالت، تعداد دورها و ظرفیت میز را تعیین کن.
۲. «شروع مسابقه» به quick_match متصل می‌شود. بازیکنان با حالت/دور/ظرفیت یکسان هم‌اتاق می‌شوند. میز کامل فوراً شروع می‌شود؛ پس از ۵ ثانیه ظرفیت با کامپیوتر تکمیل می‌شود.
۳. «با دوستان» اتاق خصوصی می‌سازد یا با کد اتاق وارد می‌شود. همه آماده شوند و میزبان شروع کند. تکمیل خودکار میز در این مسیر اختیاری است.
۴. در «دوستان» کد بازیکن را مبادله کنید، درخواست دوستی بفرستید و تأیید کنید. هر بازیکن فقط پروفایل خودش را ویرایش می‌کند. فهرست و درخواست‌ها پس از راه‌اندازی دوباره سرور باقی می‌مانند.
۵. «دعوت به بازی» از فهرست دوست تأییدشده، در صورت لزوم میز خصوصی تازه می‌سازد. دعوت داخل خود بازی دریافت می‌شود؛ گیرنده تا ۶۰ ثانیه می‌تواند بپذیرد یا رد کند. دعوت برای میز شروع‌شده، پُر یا بسته معتبر نیست؛ داشتن دوستی به‌تنهایی مجوز دعوت به میز شخص دیگری نمی‌دهد.

بازی آفلاین و انتخاب نوبتی روی یک دستگاه حذف شده‌اند. کلاینت بسته‌بندی‌شدهٔ HTML نیز بدون سرور مسابقه نمی‌سازد.

## هویت و ذخیره

شناسهٔ مهمان ۸ کاراکتری و توکن تصادفی هنگام اولین اتصال ساخته می‌شوند. توکن برای همان مرورگر/مبدأ و آدرس سرور در localStorage است؛ فقط هش توکن همراه نام، آواتار، دوستی‌ها و درخواست‌ها در .local/social.json ذخیره می‌شود. این فایل در Git نیست. حساب ایمیل/موبایل یا بازیابی بین دستگاه‌ها وجود ندارد. پاک‌کردن localStorage یا تغییر مبدأ آدرس ممکن است مهمان تازه بسازد. فایل سرور را برای حفظ فهرست دوستان نگه دارید. حضور و دعوت‌ها در حافظه‌اند و با راه‌اندازی مجدد پاک می‌شوند. در چند پردازه/چند میزبان باید ذخیرهٔ مشترک جایگزین این فایل شود؛ نسخهٔ فعلی تک‌پردازه است.

API /api/social با توکن Bearer کار می‌کند؛ snapshot فقط اطلاعات مجاز همان بازیکن را برمی‌گرداند. درخواست دوستی تأیید لازم دارد. دعوت فقط پس از کنترل دوستی، عضویت دعوت‌کننده، مرحله و ظرفیت میز صادر می‌شود. نام و آواتار اتصال دارای هویت را سرور از پروفایل معتبر می‌گیرد. اتاق‌ها برای کلاینت‌های مهمان قدیمی SDK هم قابل تست‌اند، اما دعوت فقط برای هویت معتبر ممکن است.

## قواعد سرور

هر نفر ۵ ثانیه مهلت دارد؛ اولین انتخاب معتبر قفل می‌شود، پیام نامعتبر/دست قدیمی رد می‌شود. حرکت‌ها تا ثبت همه خصوصی‌اند. پایان زمان انتخاب‌های ناتمام را با حرکت معتبر تصادفی تکمیل می‌کند. پس از نمایش، ۲٫۲ ثانیه تا دست بعد فاصله است. قطع موقت ۳۰ ثانیه بازیابی دارد؛ خروج عمدی یا تمام‌شدن مهلت اتصال، بازی جاری را بدون ثبت نتیجه لغو می‌کند. نتیجهٔ نهایی سرور در رکورد همین دستگاه ذخیره می‌شود؛ جدول جهانی وجود ندارد.

## بررسی

npm run test:online شامل قواعد، محرمانگی، اتصال مجدد، مچ‌میکینگ و tests-online/social.test.mjs برای تأیید دوستی، جلوگیری از دعوت جعلی، انقضا، ماندگاری و حذف دوطرفه است. npm run test:browser جریان دو مرورگر مستقل از ثبت پروفایل تا دعوت و مسابقه را تست می‌کند. npm run test:viewport صفحه‌های آنلاین و فهرست‌های صفحه‌بندی‌شده را در هفت اندازه بررسی می‌کند. اتصال گوشی فیزیکی روی Wi-Fi همچنان نیازمند تست کاربر است.
